# Уроки боевого окна 9 августа: три структурных дыры

Все три найдены на приватном наборе (`f1dc75c17f9a5e55`) в окне сдачи. Первая
закрыта веткой `fix/ledger-doc-keys`, вторая и третья — бэклог с разбором.
Общий корень у всех: публичный офлайн-гейт (35.00) на эти механизмы слеп —
на публичном наборе соответствующие ветки кода либо не исполняются вовсе,
либо не имеют расхождений.

## 1. Леджерные doc-ключи (починено этой веткой)

Приватные договоры оперируют ~60 документальными показателями против трёх
публичных, и часть из них — не документальные вовсе: `principal_payments` в
знаменателе DSCR не назван числом ни в одном документе, потому что это
агрегат по леджеру («выплаты тела долга за период»). Адресный числовой резолв
честно возвращал «не найдено», спека оставалась невалидной, ячейка уходила на
приор — при том, что и метрика, и порог, и цитата были извлечены правильно.
Боевая цена: минимум одна ячейка (DSCR 1.235 против порога 1.25 — посадка
«впритык», статус решал приор с чужой семьёй).

Починка — второй ярус резолва (`facts_extract.resolve_doc_metric` +
`solve._resolve_ledger_doc_metrics`): модель по цитате пункта выписывает
формулу DSL для величины, грамматика и таксономия её валидируют, `doc(<ключ>)`
в метрике заменяется выражением текстуально, спека перечекивается. Инвариант
«LLM читает, код считает» сохранён буквально: модель не возвращает ни одного
числа. Эхо порога исключено синтаксически — `const()` в выражении запрещён и
промптом, и проверкой AST; `doc()` внутри выражения запрещён тоже. Чинятся
только спеки, невалидные исключительно из-за недостающих ключей: при
`quote_unverified`/`limit_not_in_quote` метрике нельзя верить целиком. Любой
отказ на любом шаге — прежнее поведение (лестница).

Слепота гейта: на публичном наборе неразрешённых doc-ключей нет, ветка не
исполняется, 35.00 её не меряет. Замер эффекта — только живым прогоном по
набору с такими ключами; кассету после живых вызовов дозаписать
`make cassette-freeze`.

## 2. Кэш categorize_llm — по батчу, а не по описанию (бэклог)

Ярус-2 категоризации батчит OTHER-описания по 50 и кэшируется ключом от текста
всего промпта. Следствие, пойманное боевым прогоном: правка регулярок яруса-1
изменила СОСТАВ батча (64 описания → 44) → другой текст промпта → промах
кэша → модель заново переголосовала все 44, включая сорок, которых правка не
касалась. Итог: выручка одного заёмщика (7.6M, единственная опора ковенанта
«минимальная выручка») в попытке 1 была категоризирована верно, в попытке 2 —
нет; шесть ячеек обнулились, шесть перевернулись BREACH → COMPLIANT. Правку
регулярок пришлось откатить целиком — не потому, что регулярки неверны (они
двигали 24 строки правильно и 0 публичных), а потому что любая их правка —
скрытый перекат всей LLM-категоризации заёмщика.

Починка (не в окно): ключ кэша яруса-2 — по одному описанию
(`sha256(model + prompt_шаблон + description)`), батчинг — только
транспортная оптимизация поверх. Тогда правка регулярок трогает ровно те
строки, которых касается. Слепота гейта: на публичном наборе ярус-1 покрывает
всё и categorize_batch не вызывается вообще — 35.00 не меряет LLM-категоризацию
ни на байт.

## 3. «Операция признаётся в периоде X» — класса фактов нет (бэклог)

В фактах есть `reclass`, `exclude`, `amount_override` — но нет переопределения
ковенантного периода. Боевой пример: единственная строка леджера за границей
календарного года (выручка от 2026-01-05), и AUP-отчёт прямо пишет «включена
в ковенантный период 2025 года по методу начисления». Наш дефолт (суммировать
всё) оказался прав случайно. Попытка перенести `period(...)` извлечённой
формулы в шаблон при подмене (казалось бы, безобидная точность) обнулила
выручку этой ячейки: механический фильтр по дате задавил документальное
решение аудитора. Перенос откатили; решение закреплено пином
`test_substituted_template_does_not_inherit_period_filter`.

Починка (не в окно): класс фактов `period_override` — «txn X принадлежит
периоду Y по документу Z» — с цитатой, применяемый в `prepare_rows` наравне с
`exclude`. Пока его нет, ЛЮБОЙ фильтр периода в исполняемой формуле спорит с
документами, а не опирается на них; исключения из периода выражаются только
ярусом фактов (`excluded_txns`).
