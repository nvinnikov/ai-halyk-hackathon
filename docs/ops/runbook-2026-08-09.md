## 11:00 — приватный архив на диске


Читать в выводе ровно три вещи:

2. **`pdf_count`** — сколько документов приехало. Резко больше 200 → прогон

## 11:05 — боевой прогон

```bash
make run ARCHIVE=$ARCHIVE          # = ./run.sh, .env подхватывается сам
```

`ARCHIVE` для `run` и `sanity` обязателен: без него цель падает с подсказкой.
Раньше у переменной был дефолт на публичный зип, и забытое `ARCHIVE=` молча
считало публичный набор и перезаписывало `out/submission.json` — прогон
формально успешен, сказать об этом было некому.

У `run` гейт строже, чем у `sanity`: публичный архив он не принимает и явно
названным. `sanity` ничего не пишет и обязан пускать публичный набор — на нём
держится предполётная проверка стоп-строки; `run` перезаписывает отправляемый
файл, и публичный архив здесь не бывает верным. Если `export ARCHIVE=` остался
в оболочке с репетиции, `make run ARCHIVE=$ARCHIVE` скажет об этом до прогона,
а не после перезаписи.

**Сколько это займёт.** Холодный публичный прогон — **138** вызовов LLM,
замер по `schema_version`:

| Стадия | Вызовов | Масштабируется |
| --- | --- | --- |
| `route-meta` | 67 | документами с целевым счётом |
| `facts` | 38 | документами в досье |
| `specs` | 12 | заёмщиками |
| `ownership` | 12 | заёмщиками |
| `vision` | 8 | **слепыми СТРАНИЦАМИ**, а не документами |
| `docfact` | 1 | адресный резолв |

Троттл в `llm.py` глобальный на процесс и держит лок во время сна, поэтому
`SOLVE_WORKERS` пропускную способность не поднимает:

```
вызовов ≈ документы_с_целевым_счётом + документы_в_досье + 2 × заёмщиков + blind_pages
время ≥ вызовов × GEMINI_MIN_INTERVAL_MS
```

**Наблюдено, а не вычислено** (репетиция 8 августа, `live-rehearsal-2026-08-08.md`):
публичный набор целиком в сеть — **18.4 минуты, 138 вызовов, $0.81**. Из 6.7 с
на вызов 5.0 — собственный троттл, ~1.7 с — сеть. На вдвое большем приватном
наборе ждать ≈ 35–40 минут. Окно выдерживает с запасом.

Пересчитывая на приватный набор, не забыть `blind_pages`: это единственное
слагаемое формулы, которое считается **страницами**, а не документами, и
масштабируется отдельно от остальных. На публичном наборе их 8 из 138 вызовов —
незаметно; скан-тяжёлый приватный набор со 150 слепыми страницами добавит 150
вызовов, то есть ещё ≈ 17 минут при наблюдённых 6.7 с, и оценка «вдвое больше
документов → вдвое дольше» окажется вдвое оптимистичной. Число печатает сам
`make sanity` строкой `blind_pages` — подставлять оттуда, до прогона.

Интервал в окне **не крутить**: 7.5 вызовов/мин у границы бесплатного тарифа, и
429-шторм дороже восемнадцати минут. Повторные прогоны почти бесплатны — кэш
переживает перезапуск, платит только первый. Если 429 всё же пошли — поднимать
интервал, а не понижать.

Детерминизм даёт **кэш, а не модель**: на репетиции 34 ответа из 123 разошлись
с замороженными в кассете, при неизменном итоге. Повтор по прогретому workdir
воспроизводится байт в байт, повтор с нуля — нет. Поэтому `make submit` после
каждого прогона-кандидата.

Первые две строки лога — контрольные:

```
dataset_hash: <не публичный>
provider: gemini gemini-3.6-flash
```

`provider: anthropic` означает, что `.env` не прочитался — **прервать, поправить,
перезапустить**. Кассета и все замеры сняты под gemini; anthropic пойдёт вслепую
и по деньгам.

Скорер после прогона **молчит** — это правильно: публичный `ground_truth.json`
к приватному набору не относится (`solve.py::_is_public_dataset`). Строка
`скорер пропущен: публичный ground_truth не от этого набора` — норма, а не сбой.

Пока идёт — не трогать `out/`. Файл там валиден на любой секунде.

## Снапшот отправки

```bash
make submit
```

Кладёт `out/submission-<N>.json`, `out/cache-<N>/` и `run-report-<N>.json` — та
самая попытка воспроизводима байт в байт. Делать **после каждого** прогона,
который считаете кандидатом на отправку: следующий `make run` перезапишет
`out/submission.json`.

`submit` сам откажется снимать снапшот с публичного прогона:

```
!!! ОТКАЗ: прогон шёл по ПУБЛИЧНОМУ НАБОРУ !!!
```

Это последняя линия, и она нужна потому, что публичный прогон — штатный путь:
`make solve` и `make determinism` его прямо предполагают, а оба оставляют в
`out/submission.json` ответы по публичному набору. Отказ означает ровно одно —
перезапустить `make run ARCHIVE=<приватный>`. Если происхождение прогона
установить не удалось (нет `run-report.json`), снапшот снимается как есть и
печатает об этом строку: неотправленная работа хуже сомнительной.

**Обход — `SUBMIT_FORCE=1 make submit`.** Он нужен, потому что вердикт под
отказом эвристический: публичность определяется сравнением байтов леджера, и
приватный пакет с тем же `master_ledger_2025.csv` (документы другие, шаблон
другой) опознается как публичный. Признак ложного срабатывания простой — вы
только что прогнали приватный архив, `dataset_hash` в логе не публичный, а
`submit` всё равно отказывает. Тогда обход, и дальше по плану: **без него
единственный выход — копировать `out/submission.json` в
`out/submission-<N>.json` руками**, а под таймером это лишняя минута на
догадку.
