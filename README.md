# ai-halyk — Agentic Bank

**Ковенантный мониторинг корпоративных кредитов.** Пайплайн читает 200 PDF
заёмщиков и банковский леджер за год (1473 проводки) и по каждому финансовому
ковенанту отвечает тремя полями: соблюдён или нарушен, фактическое значение
показателя, транзакция-улика. 12 заёмщиков × 3 ковенанта = 36 ячеек ответа.

Решение кейса Halyk AI Challenge, август 2026. Датасет задания лежит
в репозитории целиком (`dataset/agentic-bank-public/`), окружение пинится
`uv.lock` — всё, что написано ниже, проверяется прогоном, а не на слово.

> **In English.** Covenant monitoring for corporate loans: the pipeline reads
> 200 borrower PDFs plus a year of bank ledger and, for every financial
> covenant, returns compliance status, the actual metric value and the
> transaction that caused a breach. The engineering point is not "an LLM reads
> documents" — it is turning a non-deterministic model into a measurable
> system: regression score gates in CI, a recorded LLM cassette that replays
> the whole pipeline offline for free, mutation tests that derive the expected
> answer *without* our own engine, and a hard split where the model only reads
> text with verbatim quotes while all arithmetic lives in code.
>
> It scored 35.00/36.00 on the public set and then placed 51st of 186 on the
> hidden one. **The interesting half of this repo is what happened next.** A
> top-10 team published the hidden dataset (it is in this repo, with the
> organisers' permission), which gave a measurement loop, and
> a written post-mortem turned into three waves of fixes that moved the score
> from 65.58% to 91.65% against a proxy key — with no architectural changes at
> all. The repo keeps the negative results too: a de-noising stage that was
> built, measured at −5.79 points and rejected, and two cells I declared
> unwinnable that the existing LLM tier solved once I stopped asking whether a
> deterministic rule could. See
> [Что в этом кейсе стоит смотреть](#что-в-этом-кейсе-стоит-смотреть) and
> [Что пошло не так](#что-пошло-не-так-и-как-это-чинилось).

## Бизнес-задача

Кредитный договор содержит финансовые ковенанты — «долг к EBITDA не выше 3.5»,
«капитальные затраты Группы не более 4% выручки», «доля выплат связанным
сторонам ниже порога». Банк обязан проверять их регулярно, а исходные данные
для проверки лежат в двух несовместимых мирах: числа — в транзакционном
леджере, а правила, исключения и реклассификации — в PDF (аудиторские отчёты,
записки казначейства, дополнительные соглашения, KYC-структуры владения,
консолидированная отчётность материнской компании). Сегодня это ручная работа
кредитного аналитика по каждому заёмщику, и она не масштабируется.

Цена ошибки несимметрична, и это определило всю архитектуру:

- **Ложное «соблюдён»** — банк не заметил ухудшения и не сработал ковенантным
  триггером; риск уезжает в дефолт неучтённым.
- **Ложное «нарушен»** — банк предъявляет клиенту требование по ошибке;
  это репутационный и юридический ущерб.
- **Молчание** (не смогли посчитать) дешевле обоих, но только если система
  честно об этом говорит, а не выдаёт уверенное число.

Отсюда `status` весит больше, чем точность значения (0.50 против 0.30 в
скоринге кейса), отсюда fail-open на уровне ячейки: любой сбой не роняет
прогон, ячейку добирает лестница фолбэков, а причина уходит в лог как `ALARM`.
Отсюда же `evidence_txn_id = null` — это правильный ответ, а не пробел:
транзакция-улика существует, только когда откат ровно одного документального
решения переворачивает вердикт.

Отдельное ограничение задачи, которое хорошо переносится на прод: приватный
набор заёмщиков открывался в день сдачи, окно — 3 часа. То есть систему нельзя
было подогнать под данные, на которых её разрабатывали. Полный холодный прогон
занимает **18.4 минуты и $0.81** (замер живой репетиции, 138 вызовов модели).

## Что в этом кейсе стоит смотреть

Три вещи, и ни одна из них не про «прикрутить LLM к документам».

### 1. Eval-дизайн: как измерять систему, у которой нет градиента

Никакого дообучения здесь нет — есть 36 ячеек и правки в коде. Единственный
способ отличить улучшение от совпадения — построить измерение раньше, чем
пишешь правку.

| Инструмент | Что он ловит |
| --- | --- |
| Два порога скора в CI (`BASELINE`, `EXTRACTED_BASELINE`) | Регрессию. Улучшил — подними порог тем же коммитом, иначе откат назад не поймается. Пороги разные: один стережёт расчётное ядро на эталонных фактах, второй — боевой путь с извлечением из PDF. |
| Кассета `eval/cassette/` | Стоимость эксперимента. Весь конвейер прогоняется офлайн, бесплатно и детерминированно — правка меряется за минуту, а не за 18. CI работает без ключей API. |
| Мутации (`eval/mutations*.py`) | Самосогласованность. Датасет мутируется целиком — переименование компаний, сдвиг порога в тексте договора, смена валюты, — и ожидаемый ответ выводится **без нашего движка**. Иначе тест меряет, что решение согласно само с собой. |
| LOBO (`eval/lobo.py`) | Подгонку под заёмщика: 12 прогонов, каждый раз один заёмщик решается без библиотеки шаблонов. |
| Греп-гейт (`eval/grep_gate.py`) | Утечку знания о наборе в код: ни одного имени заёмщика, номера пункта, порогового числа или префикса `TXN-`/`ACC-` в `solution/` — список запрещённого строится из самих eval-данных. |
| Теневой расчёт (`solve._shadow_compare`) | Цену собственных эвристик. Там, где шаблон подменяет извлечённую моделью формулу, считаются **оба** значения, и алярм поднимается, только если подмена изменила ответ, — получается поимённый список ячеек, которые на новом наборе надо смотреть глазами. |

Практический результат этой дисциплины виден в истории: правило, дававшее
+1.00 на проблемной ячейке и −1.00 на каждой из двух других, было отвергнуто
**до** того, как организаторы подтвердили, что там опечатка в датасете.
Отвергнуто не по интуиции, а по замеру.

**Переносимость проверена не на бумаге.** Боевой набор открылся в день сдачи и
оказался в 2–3 раза больше того, на котором система разрабатывалась:

| | Открытый набор (в репозитории) | Боевой набор |
| --- | --- | --- |
| Сценариев / ячеек ответа | 12 / 36 | 27 / 84 |
| PDF-документов | 200 | 305 |
| Проводок в леджере | 1473 | 2355 |

Пайплайн отработал в окне и выдал ответ по всем ячейкам без правок под данные.
**Закрытый набор лежит в репозитории целиком**, распакованным каталогом, как и
публичный, — организаторы разрешили его публикацию, — поэтому всё, что
написано ниже про разбор, проверяется прогоном, а не на слово: `make
hidden-archive` собирает архив из каталога, `make verify-hidden
ARCHIVE=6a7819a8cb7d3480322468.zip` сверяет данные внутри него (леджер и
шаблон ответа), `make private-score` печатает скор. Ценнее другого:
прогон вскрыл три механизма, к которым публичный гейт 35.00 **слеп по
построению** — соответствующие ветки кода на открытом наборе либо не
исполняются вовсе, либо не имеют расхождений. Один из них (кэш
LLM-категоризации по батчу, а не по описанию) стоил шести перевёрнутых ячеек
из-за правки регулярок, которая этих строк даже не касалась. Разбор всех трёх с
ценой в баллах и планом починки лежит в `docs/ops/` — post-mortem, а не
победный отчёт.

### 2. Детерминизм при недетерминированном компоненте

Модель недетерминирована, и это замерено, а не предположено: на живой
репетиции из 123 промптов, общих с записанной кассетой, **34 ответа (28%)
разошлись** с замороженными — а итоговый скор не сдвинулся ни на балл
(`docs/ops/live-rehearsal-2026-08-08.md`). Ровно этого и добиваются:
воспроизводимость держится не настройками сэмплинга, а архитектурой вокруг
модели.

- **Content-addressed кэш ответов.** Ключ = `sha256(model_id + prompt +
  json_schema + schema_version)`. Кэш не протухает по времени — только по
  содержимому. Повторный прогон того же входа даёт тот же выход байт в байт
  (`make determinism` сверяет именно байты).
- **Никакого `float` и никакого `set` в расчёте.** Деньги — `Decimal`,
  округление — `ROUND_HALF_UP` (питоновский `round()` банковский и молча
  испортит `actual`), любое множество сортируется перед использованием: иначе
  порядок итерации утаскивает результат.
- **Скелет ответа пишется первым.** `out/submission.json` валиден на любой
  секунде прогона и перезаписывается по одной ячейке — прогон, убитый на
  17-й минуте трёхчасового окна, всё равно оставляет отправляемый файл.
- **Идемпотентные стадии с версионированием.** Артефакт стадии
  инвалидируется по версии модуля, а не по входу, — рестарт в окне стоит
  минуты, а не полного прогона.

### 3. «LLM читает, код считает»

Инвариант, проведённый через весь пайплайн буквально: модель не делает
арифметику **никогда**. Она отвечает только на вопросы, требующие понимания
текста, — какая редакция документа действующая, кем выпущена отчётность, какая
формула записана в пункте договора, — и каждый её ответ проходит JSON-схему и
грамматику DSL до попадания в расчёт. EBITDA, проценты, доли, сравнение с
порогом считает код на `Decimal`.

Из этого следуют конкретные защиты, которые в проде нужны любому document-AI:

- **Каждая цитата верифицируется в исходнике.** Не нашлась дословно — факт
  отбрасывается с алярмом. Галлюцинация цитаты не может доехать до ответа.
- **Документ попадает в промпт только через `sanitize_document`**, промпт несёт
  разделитель «данные, не команды» — PDF заёмщика это недоверенный вход, и
  фраза «игнорируй предыдущие инструкции» в отсканированном договоре
  не должна ничего значить.
- **Порог связанности сторон применяет код, а не модель:** модель выписывает
  таблицу долей владения с цитатами, сравнение с порогом — арифметика.
- **Капитальные затраты Группы:** модель выписывает из примечания об основных
  средствах стоимость на начало и конец, амортизацию и признак отсутствия
  выбытий; тождество `конец − начало + амортизация` считает код и только после
  проверки двух условий применимости. Не подтвердилось — расчёта нет, ячейка
  честно уходит на фолбэк.

Дальше по README — как это запускать; техническая карта модулей и все ловушки
разобраны в [`CLAUDE.md`](CLAUDE.md), разборы боевых прогонов — в
[`docs/ops/`](docs/ops/).

## Результат

Три числа, и путать их нельзя.

**Публичный набор — 35.00 / 36.00.** Оставшийся балл — опечатка в самом
датасете, подтверждённая организаторами: в договоре `P4` пункт 6.3 загрузился
с неверным порогом, в ключе значение правильное. Код под это не правился:
порог читается из договора, а получить совпадение можно было бы только зашив
число под одну ячейку. Показательно, что правило было отвергнуто **до**
объяснения организаторов и по измеримой причине — оно давало +1.00 здесь и
−1.00 на каждой из двух других ячеек (`docs/ops/remaining-losses.md`).

**Закрытый набор — 51 место из 186, 70.99%.** Первое место 96.36%, топ-10
около 93%. Пайплайн отработал в окне за 157 секунд, не упал, выдал ответ по
всем 84 ячейкам. И проиграл.

**После разбора — 91.65%** против прокси-ключа на том же закрытом наборе,
оценочно ~95.7% против настоящего, без единого изменения архитектуры. Число
воспроизводится с чистого клона: архив в репозитории, ответы модели в кассете,
`make private-score` печатает его за минуту без сети и без ключей.

## Что пошло не так и как это чинилось

Это половина репозитория, и она интереснее первой.

### Разбор

Команда из топ-10 выложила своё решение вместе с **байт-идентичным закрытым
архивом** — это дало то, чего не было в окне: возможность мерить. Разбор
(`docs/ops/private-set-postmortem.md`) нашёл шесть причин, и ни одна из них не
про «модель плохо читает»:

| причина | цена |
| --- | --- |
| «Операционные расходы» прочитаны как вся операционка, а договор имел в виду одну статью | 3.60 |
| Доля владения считалась по строке таблицы, а не по цепочке | 3.00 |
| Ковенант меряет любой квартал — считали год | 2.80 |
| Улика отдавалась пустой там, где догадка бесплатна по правилам скоринга | 1.40 |
| Метрика, тождественно равная порогу, давала уверенное «соблюдено» | 0.50 |

Общий корень один: **словарь предметной области был решён до того, как
прочитаны документы закрытого набора.** У нас был греп-гейт, запрещавший в коде
имена заёмщиков, номера пунктов и пороговые числа, — он честно ловил *видимую*
подгонку под публичный набор. Невидимая (что значит термин, что тесты годовые,
что леджер чист) заехала в дизайн без единого вопроса, потому что выглядела не
как подгонка, а как знание домена.

### Починка, и как она мерялась

Каждая правка проверялась **заранее посчитанным по нашему же леджеру
значением** — то есть была проверкой гипотезы, а не догадкой. Три волны:
65.58% → 79.03% → 86.30% → 91.65%. Каждый шаг — общее правило, а не правка под
конкретного заёмщика; на публичный порог 35.00 не сдвинулся ни один из них.

### Отрицательный результат, который остался в репозитории

Один из шести пунктов разбора оказался **неверным**. Закрытый леджер на 87%
состоит из подсаженных строк, и напрашивался ярус их отсева. Он был построен,
измерен живым прогоном и **стоил бы 5.79 балла**: восемь ячеек изменились, все
восемь в минус. Причина — шум не доходит до метрики: читаемые категории
содержат единицы строк, и это настоящие строки.

Разбор лежит в `docs/ops/ledger-noise.md` именно затем, чтобы следующий
читатель не начал строить этот ярус заново. Там же — поправка к собственной
ошибке измерения: сначала было записано, что в публичном наборе подсадных строк
нет вовсе; на деле генератор один и тот же, а отличается только разброс сумм.

### Число, которое держалось на тёплом артефакте

Публикация закрытого архива поставила вопрос, которого до того не было:
воспроизведёт ли замер свежий клон? Проверка — стереть `work/` и прогнать
только на кассете — заняла две минуты и стоила 0.50 балла честности. Вместо
заявленных 92.25% вышло 89.51%: у одного заёмщика промахивалась кассета на
извлечении спек, и тёплый артефакт стадии это скрывал, потому что артефакты
инвалидируются по версии, а не по содержимому промпта.

После починки кассеты и двух прогонов с абсолютного нуля — **91.65%,
устойчиво и без единого промаха**. Заявленные 92.25% не были подтасовкой: они
были измерены честно, но на состоянии, которое нельзя передать. Разница между
«я это измерил» и «это можно измерить заново» здесь ровно полбалла, и узнать её
лучше до того, как число попадёт в резюме.

### Где ошибался я сам

- **Дважды объявил ячейку невзятой** — и оба раза оценивал, справится ли
  *детерминированное правило*, перенося ответ на задачу целиком. По одной я
  даже посчитал наивную формулу и получил 1.2654 против ключевых 1.23. Модель,
  прочитав цитату пункта, написала формулу точнее моей.
- **Зелёная метрика не отличала «работает» от «молчит».** Проверка формы
  показателя давала ноль расхождений и выглядела здоровой, пока не выяснилось,
  что целая её ветка была мертва с рождения и не могла сработать ни разу.
- **Ревью дважды ломало код, чтобы проверить тесты.** Оба раза тесты проходили
  и без защиты, которую якобы проверяли.

Переносимая часть всего этого вынесена отдельным файлом —
`docs/ops/playbook-eval-tasks.md`: чеклист по фазам задачи с закрытым набором,
подход «модель определяет словарь, код считает», и план перевода решения на
него.

## Быстрый старт

```bash
make public-archive                   # собрать публичный архив (в git не хранится)
./run.sh 6a741640c31eb032062683.zip   # единственная точка входа: архив → out/submission.json
make solve                            # то же самое через make (ARCHIVE=... переопределяет архив)
make check                            # локальный CI-гейт: lint + typecheck + tests
```

Вход пайплайна — zip-архив датасета, а `*.zip` в `.gitignore`, поэтому на свежем
клоне публичный архив надо собрать: `make public-archive` пакует
`dataset/agentic-bank-public/` в `6a741640c31eb032062683.zip`. Тем же кодом
(`tools/public_archive.py`) пользуются CI и `tests/conftest.py` — иначе байты
архива, а с ними и `dataset_hash`, разошлись бы. На боевом прогоне архив
приходит аргументом и уже существует.

Закрытый набор устроен точно так же: `dataset/agentic-bank-hidden/` лежит в
репозитории целиком (см. [«Результат»](#результат)), `make hidden-archive`
пакует его в `6a7819a8cb7d3480322468.zip` тем же упаковщиком
(`tools/hidden_archive.py`).

Окружение поднимает [uv](https://docs.astral.sh/uv/) из `uv.lock`, Python пинится
`.python-version`. Все скрипты рассчитаны на запуск **из корня репозитория** —
пути к датасету относительные.

Провайдер LLM выбирается через `LLM_PROVIDER` (`anthropic` | `gemini`), ключи и
реквизиты команды — из `.env` (его читает `run.sh`; в git он не хранится).
Провайдер и модель прогон печатает второй строкой, сразу после `dataset_hash`, —
если там не то, что ожидали, значит `.env` не прочитался.

Шаблон окружения — `.env.example`, со всеми переменными и их смыслом:

```bash
cp .env.example .env    # и заполнить ключи + реквизиты команды
```

## Прогон без сети

```bash
LLM_OFFLINE=1 LLM_PROVIDER=gemini uv run pytest -m llm -q   # весь конвейер офлайн
make cassette-freeze                                        # дозаписать живые вызовы
```

`eval/cassette/` — записанные ответы модели, **тестовая фикстура, а не продовый
артефакт**. Порядок чтения: кассета → `work/llm_cache/` → сеть; при
`LLM_OFFLINE=1` промах обоих кэшей это ошибка, а не поход в сеть. Ключ считается
от текста промпта, а в промпте лежат документы, поэтому на другом датасете
попаданий не будет — так и задумано. Смысл кассеты в том, чтобы прогонять весь
конвейер офлайн, бесплатно и детерминированно: замерить правку за минуту и
держать CI без ключей.

## Структура

| Путь | Что внутри |
| --- | --- |

| `solution/ledger.py`, `fx.py`, `engine.py` | Распаковка архива, устойчивый разбор и категоризация леджера (`categorize*.py`), валютная нормализация, Decimal-агрегация. |
| `solution/dsl.py`, `interp.py`, `templates.py` | Грамматика метрик, интерпретатор со знаковым вердиктом, библиотека шаблонов с сигнатурным матчем. |
| `solution/evidence.py`, `fallbacks.py` | Улика откатом документального решения; лестница фолбэков (спека → эвристика → приор). |
| `solution/pdftext.py`, `vision.py`, `route.py`, `dossier.py`, `facts_extract.py`, `specs_extract.py` | Документный слой: постраничный текст, vision по слепым страницам, маршрутизация (строгая по номеру счёта + второй проход по наименованию заёмщика для отчётности группового уровня), сшивка досье с выбором действующей редакции и областью видимости документа, факты и спеки с цитатами. |
| `solution/guard.py`, `llm.py`, `stages.py` | Защита от prompt-injection и галлюцинаций цитат; LLM-клиент с content-addressed кэшем и кассетой; идемпотентные стадии. |
| `solution/solve.py` | Harness: скелет-первым `out/submission.json`, fail-open на ячейку, трейс в `work/<hash>/trace/`. |

| `tools/verify_hidden.py` | Сверка данных закрытого набора по sha256: леджера и шаблона ответа внутри архива (не архива целиком — его байты зависят от упаковщика, а не только от датасета). |
| `tools/score_private.py`, `eval/private_proxy_key.json` | Контур замера на закрытом наборе: скорер по официальной формуле и прокси-ключ (опубликованный ответ команды со второго места, не истина). |
| `tools/public_archive.py`, `tools/hidden_archive.py` | Сборка архивов датасетов из распакованных каталогов — общий воспроизводимый упаковщик (`pack_dataset`), два каталога-источника и два имени архива. ## Команды

| Команда | Что делает |
| --- | --- |
| `make install` | `uv sync --extra dev` |
| `make public-archive` | Собрать `6a741640c31eb032062683.zip` из `dataset/agentic-bank-public/` |
| `make hidden-archive` | Собрать `6a7819a8cb7d3480322468.zip` из `dataset/agentic-bank-hidden/` |
| `make solve` | Прогнать решение (`./run.sh`), записать `out/submission.json`, напечатать скор |
| `make lint` | `ruff format --check` + `ruff check` |
| `make typecheck` | `mypy` |
| `make test` | `pytest` |
| `make check` | Всё вышеперечисленное — зеркало CI |
| `make eval-offline` | Инварианты, греп-гейт и юниты без сети |
| `make cassette-freeze` | Дозаписать `work/llm_cache/*.json` в `eval/cassette/` |
| `make sanity ARCHIVE=<архив>` | Санитарные проверки прогона |
| `make verify-hidden ARCHIVE=<архив>` | Сверить данные закрытого архива (леджер, шаблон ответа) по sha256 с тем, на котором считались числа разбора |
| `make private-score` | Скор `out/submission.json` против прокси-ключа закрытого набора |
| `make run ARCHIVE=<архив>` | Боевой прогон по заданному архиву (без пересборки публичного) |
| `make determinism ARCHIVE=<архив>` | Два прогона подряд, байт-диф `submission.json` |
| `make submit` | Снапшот отправки: `submission-<N>.json` + `cache-<N>/` + `run-report-<N>.json` |

`ARCHIVE` у `run`, `sanity` и `determinism` обязателен: все трое пишут или
читают `out/submission.json`, и молчаливый дефолт на публичный зип стоил бы
отправляемого файла. Публичный набор гоняется через `make solve`.

## CI

- **`.github/workflows/ci.yml`** — на push и PR в `master`: lint, typecheck,
  тесты и end-to-end прогон `./run.sh`, плюс сканирование секретов
  (gitleaks, конфиг в `.gitleaks.toml`).
- **`.github/workflows/claude-review.yml`** — автоматический review PR. Требует
  секрет репозитория `CLAUDE_CODE_OAUTH_TOKEN`; без него джоба скипается.
  **Правила ревью — в `.github/REVIEW.md`**, тюнить надо там: правка самого
  workflow отключает ревью на том же PR (защита `claude-code-action`).
- **`.github/workflows/claude.yml`** — ассистент по упоминанию `@claude`
  в комментариях к PR и issue.

Регрессионных порогов скора два, и оба входят в `make check`:
`BASELINE` в `tests/test_solution.py` стережёт expected-режим (расчётное ядро),
`EXTRACTED_BASELINE` в `tests/test_extracted_gate.py` — боевой extracted-путь
(офлайн, из замороженной кассеты `eval/cassette/`). Улучшили решение — поднимите
соответствующий порог тем же коммитом, тогда откат назад поймается сразу.

Есть ещё floor-тест в `tests/test_extracted_run.py`, но он помечен маркером
`llm` и в CI не идёт: боевой путь стережёт именно `EXTRACTED_BASELINE`. Путать
их дорого — порог, поднятый не в том файле, оставляет CI слепым.
