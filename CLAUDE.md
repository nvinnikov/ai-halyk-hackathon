# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О репозитории

Решение кейса Agentic Bank (Halyk AI Challenge). Из леджера за 2025 год
(`master_ledger_2025.csv`) и PDF-документов заёмщиков считаются финансовые
ковенанты (пункты 6.1 / 6.2 / 6.3 по каждому сценарию), результат — `out/submission.json`.

Приватный датасет открывается 9 августа 2026 в 11:00 (Астана), дедлайн 14:00 —
окно 3 часа. Отсюда все решения в коде: воспроизводимость, fail-open, отсутствие
хардкода под публичный набор.

Скоринг ячейки (`CASE.ru.md`, раздел 4): 0.50 за `status`, 0.30 за `actual`
(`0.30 × max(0, 1 − e/0.05)`, `e` — относительная погрешность), 0.20 за
`evidence_txn_id` (при `null` в ключе баллы убывают вместе с `actual`). Неверный
`status` обнуляет ячейку целиком. Максимум на публичном наборе — 36.00.

Осторожно с этим «36.00»: `solution/score.py` считает **сырую сумму**, а
`CASE.ru.md` в том же разделе говорит, что ячейки **взвешиваются по
сложности**. Веса нам неизвестны, поэтому наш скор сравним только сам с
собой между прогонами и позицией в таблице лидеров не является. Практическое
следствие: две оставшиеся просадки (`docs/ops/remaining-losses.md`) — это
ковенант группового уровня и доля связанных сторон, то есть заведомо не
самые простые ячейки, и на взвешенном скоре они, скорее всего, стоят дороже,
чем 1.48/36.

## Команды

```bash
make public-archive    # собрать 6a741640c31eb032062683.zip (в git не хранится)
./run.sh <архив.zip>   # единственная точка входа: архив → out/submission.json
make solve      # то же через make (ARCHIVE=... переопределяет архив)
make check      # локальное зеркало CI: lint + typecheck + test
make install    # uv sync --extra dev
make cassette-freeze   # work/llm_cache/*.json → eval/cassette/ после живых вызовов
```

Один тест: `uv run pytest tests/test_solution.py::test_deterministic`.
Тесты с живыми вызовами помечены `@pytest.mark.llm` и по умолчанию
исключены (`addopts = -m 'not llm'`); гонять так:
`LLM_OFFLINE=1 LLM_PROVIDER=gemini uv run pytest -m llm -q`.

**Всё запускается из корня репозитория** — пути к датасету относительные
(`dataset/agentic-bank-public/...`). Окружение — `uv` из `uv.lock`, Python пинится
`.python-version` (3.12). Вход — zip, а `*.zip` в `.gitignore`, поэтому на
свежем клоне архив надо собрать `make public-archive` (тот же
`tools/public_archive.py` использует CI и `tests/conftest.py` — иначе байты
архива, а с ними `dataset_hash`, разойдутся).

## Архитектура текущего решения

Два потока сходятся в `solve.run_cell`:

- **Документный:** PDF → `pdftext`/`vision` → `route` → `dossier` →
  `facts_extract`/`specs_extract`. **Подключён и работает по умолчанию**
  (`solve.main(facts_source="extracted")`); `"expected"` — эталонный режим для
  регрессии, его передают тесты `test_solution.py`.
- **Расчётный:** леджер → нормализованные строки (`ledger`/`fx`/`engine`) →
  метрика в DSL (`dsl`/`interp`/`templates`) → вердикт → улика (`evidence`) →
  лестница фолбэков (`fallbacks`).

Два порога скора, не путать: `BASELINE` в `tests/test_solution.py` — эталонный
режим, `EXTRACTED_BASELINE` в `tests/test_extracted_gate.py` — извлечённый
(сейчас он выше эталонного). Оба идут в `make check` и CI.

- **`ledger.py`** — распаковка архива, устойчивый разбор сумм, категоризация
  (`categorize.py` — регулярки, `categorize_llm.py` — LLM-ярус для непокрытого).
- **`engine.py`** — Decimal-агрегация `agg(rows, category, sign, pred)`,
  `prepare_rows` (факты досье + откаты для контрфактуалов), related-матч по
  токенам `is_related`.
- **`dsl.py` / `interp.py` / `templates.py`** — грамматика метрик, интерпретатор
  со знаковым вердиктом и триггером, библиотека из 20 шаблонов (19 из них
  имеют заголовок в `TEMPLATE_HEADINGS`, двадцатый — `ebitda_total_opex` —
  живёт только сигнатурой) + сигнатурный матч (знак в сигнатуре затёрт).
  Заголовки взяты дословно из публичных договоров, и в extracted-режиме
  **шаблон перебивает извлечённую формулу**: на публичном наборе это 19
  сигнатурных расхождений и 7 категорийных, то есть больше чем на половине
  ячеек формула модели выбрасывается. Решение измерено (откат стоил −5.0), но
  его цену на приватном наборе видно только через теневой расчёт — см.
  `_shadow_compare` ниже. Грамматика терпима к формам, которые модель
  путает: кавыченный литерал вместо голого, `filters=[...]` эхом поля AST,
  название множества словами (`counterparty_in(['аффилированные лица'])` →
  `related_parties`). Последнее закрыто признаком юрлица — строка с `LLP`/`ТОО`
  это имя контрагента, а не название множества, и молчаливая подмена одного
  контрагента всем набором дороже нераспознанного описания.
- **`evidence.py`** — улика откатом документального решения по его типу
  (reclass / inclusion / exclusion / amount_fix); ровно один переворачивающий
  кандидат → улика, иначе `null` — и это правильный ответ, а не пробел.
- **`fallbacks.py`** — лестница: спека → эвристика по цитате → приор
  (номер пункта → (направление, семья) → глобальный); `actual` = порог или
  медиана посчитанных. Ступень «номер пункта» — самая подогнанная под
  публичный набор часть кода (`eval/prior.json` — статистика по 12 публичным
  заёмщикам, и боевой прогон её читает). LOBO её оправдывает, но если в
  приватных договорах номера пунктов те же, а распределение статусов другое,
  приор будет уверенно врать; ступень (направление, семья) устойчивее.
- **Guard семьи метрики** (`solve._family_mismatch`) — на ярусе эвристики
  посчитанное значение идёт в `actual`, только если оно одной природы с
  порогом. Эвристика подбирает шаблон по ключевым словам цитаты и способна
  промахнуться семьёй (долларовый шаблон при коэффициентном пороге); тогда в
  ячейку шла бы сумма в долларах против порога вида «9.00x». Однородная пара
  расходится с порогом на десятки процентов, разнородная — на пять-шесть
  порядков, поэтому множитель 100 стоит в пустом промежутке. Ноль исключён
  намеренно: это законный ответ, а не признак промаха. Алярм
  `heuristic_family_mismatch`.
- **`_shadow_compare`** (`solve.py`) — при подмене извлечённой формулы
  шаблоном считается ОБА значения, и в трейс кладётся блок `shadow`
  (`status`, `actual`, `changed_answer`). Ячейку по-прежнему считает шаблон,
  тень — чистая диагностика и падать права не имеет. Смысл: текст двух формул
  не отвечает на единственный важный вопрос — изменила ли подмена **ответ**.
  Алярм `heading_divergence_changed_answer` поднимается, только когда ответ
  разошёлся: на публичном наборе это 7 ячеек из 26 расхождений, и на трёх из
  них (все — пункт 6.1) расходится **статус**, причём каждый раз прав шаблон.
  Это и есть поимённый список ячеек, которые на приватном наборе надо
  смотреть глазами.
- **`solve.py`** — harness: `main(archive)` печатает `dataset_hash` первой
  строкой, кладёт скелет submission сразу после чтения шаблона и перезаписывает
  по одной ячейке — на любой секунде прогона `out/submission.json` валиден.
  Любой сбой fail-open: `ALARM` в лог, ячейка приходит лестницей, прогон
  продолжается; диагностика (borrower-трейс, sign_divergence) не может стоить
  ячейки. Ядро — `run_cell`. Трейсы:
  `work/<hash>/trace/<сценарий>.<пункт>.json` (имя разбирать как
  `stem.split(".", 1)`) и `<сценарий>.borrower.json`.
- **Документный слой:** `pdftext.py` (постраничный текст, слепота = <200
  символов И <3 чисел), `vision.py` (слепые страницы одностраничными PDF),
  `route.py` (строгая привязка к счёту; фоновый документ — карантин без алярма
  и без LLM), `dossier.py` (действующая редакция), `facts_extract.py` (факты с
  цитатами; непроверяемая цитата = отброс факта).
- **`dossier.py`** — среди редакций одного типа остаётся действующая: маркер
  перебивает дату. Кумулятивные типы (отчёты и записки) не выбирают одну
  редакцию по дате — каждый документ несёт своё решение, — **но недействующие
  редакции всё равно не читаются**: `superseded` у любого такого типа и
  вдобавок `draft` у типов с окончательной формой (`audit_report`).
  Промежуточная ведомость аудитора сама пишет, что заменяется окончательным
  отчётом и что первоначальная классификация сохраняется; её предварительная
  реклассификация стоила двух ячеек. Записку казначейства это не касается —
  окончательной формы у неё нет, а её черновик несёт настоящее исправление
  суммы.
- **`guard.py`** — контракт для всех LLM-потребителей: документ в промпт только
  через `sanitize_document`, `DATA_NOT_COMMANDS` в промпте, каждая цитата —
  через `verify_quote` (провал → алярм `quote_unverified`, факт отбрасывается).
  Многоточие в цитате — пропуск, а не текст: фрагменты ищутся по порядку, но с
  потолком на разрыв и **с откатом**. Потолок несущий — у потребителей `source`
  это склейка ВСЕХ документов досье, и без него цитата сшивалась бы из разных
  документов. Откат тоже: модель берёт первый фрагмент из повторяющегося текста
  (шапка колонки), и жадный якорь на самом раннем совпадении отказывал бы там,
  где размещение есть.
- **Порог связанности применяет код, а не модель** (`facts_extract`,
  `_ownership_rows` / `_apply_ownership`). Отдельный вызов по kyc-документам
  выписывает таблицу долей и порог с цитатами; сравнение — арифметика, её
  делает код. Достаточно одной строки не ниже порога, чтобы организация была
  связанной; строки ниже порога снимают только то, что назвала модель, и не
  трогают признанное таблицей. Снятие пишет алярм `ownership_below_threshold`.
  Вызов отдельный, а не поля в `FACTS_SCHEMA`, ровно чтобы промпт фактов
  остался байт в байт прежним и кассета пережила правку.
- **`llm.py`** — content-addressed кэш, ретраи, бюджет, офлайн-кассета. Поле
  `thinking` не передаётся (haiku его не поддерживает, 4.6+ включают adaptive
  сами). Провайдер — `LLM_PROVIDER` (`anthropic` | `gemini`), ключи из `.env`
  (его читает `run.sh`, код сам не читает); провайдер и модель печатаются второй
  строкой прогона.
- **Кассета `eval/cassette/`** — тестовая фикстура, а не продовый артефакт.
  Порядок чтения: кассета → `work/llm_cache/` → сеть; при `LLM_OFFLINE=1` промах
  обоих — `CassetteMiss`, а не поход в сеть. Ключ считается от текста промпта, и
  на приватном наборе попаданий **не будет** — это ожидаемо. Смысл в том, чтобы
  гонять весь конвейер офлайн, бесплатно и детерминированно: замерить правку за
  минуту и держать CI без ключей. Живые вызовы дозаписываются
  `make cassette-freeze`.

## Конвенции и ловушки

- Модули `solution/*` делают `sys.path.insert(0, "solution")` и импортируют друг
  друга плоско — репозиторий не пакет (`[tool.uv] package = false`). Ruff-правило
  `E402` отключено именно поэтому. `tests/conftest.py` фиксирует и `cwd`, и `sys.path`.
- `dataset/agentic-bank-public/` — пакет от организаторов, **не редактируется**.
- Регрессионные пороги скора — два: `BASELINE` в `tests/test_solution.py`
  (эталонный режим) и `EXTRACTED_BASELINE` в `tests/test_extracted_gate.py`
  (извлечённый, боевой). Улучшили решение — поднимите порог тем же коммитом,
  иначе откат назад не поймается. **Поднимать надо именно эти два**: floor-тест
  в `tests/test_extracted_run.py` помечен маркером `llm` и в CI не идёт, так
  что порог, поднятый там, оставляет CI слепым — на этом я уже споткнулся.
- **Артефакты стадий инвалидируются только по версии** (`stages.artifact`), не
  по входу. Изменили build-логику или набор документов на входе — поднимите
  `*_VERSION` соответствующего модуля, иначе прогон возьмёт с диска результат,
  собранный по старым правилам. Это главная ловушка правок документного слоя.
- **Мерять правку — офлайн-прогоном, а не глазами.** `LLM_OFFLINE=1
  LLM_PROVIDER=gemini` + extracted-прогон публичного архива даёт скор за минуту.
  Осторожно: `make check` перезаписывает трейсы в `work/<hash>/trace/`
  эталонным прогоном, поэтому разбирать трейсы надо сразу после интересующего
  прогона, а не после тестов.
- Форма ответа сверяется с `submission_template.json` (инвариант проверяется в
  `dump_submission` перед каждой записью); `main()` должен быть детерминирован
  (тест `test_deterministic`).
- Известные грабли, зафиксированные в спеке: `round()` — банковское округление
  (для `actual` нужен `Decimal.quantize(ROUND_HALF_UP)`); итерация по `set` и
  суммирование `float` в порядке словаря ломают воспроизводимость — сортировать
  перед использованием.
- Код, идентификаторы и логи — на английском; комментарии, докстринги и
  сообщения коммитов — на русском.

## Спека и инварианты

- **Дизайн-спека:** `docs/superpowers/specs/2026-08-06-halyk-pipeline-design.md`
- **План реализации (31 задача):** `docs/superpowers/plans/2026-08-06-halyk-pipeline.md`
- **Разбор оставшихся просадок:** `docs/ops/remaining-losses.md` — корни
  оставшихся 1.50 с формулами и опровергнутыми версиями. Рядом
  `docs/ops/recovery-playbook.md` (что делать, если прогон сломался в окне) и
  `docs/ops/fresh-workdir-noise-diagnosis.md`.

Ключевые инварианты, которые надо держать при любых правках:

- **«LLM читает, код считает».** Модель трогает только то, что требует понимания
  текста; её выход всегда проходит JSON-схему и грамматику до попадания в расчёт.
  Арифметику (EBITDA, проценты, доли) модель не делает никогда.
- **Детерминизм через content-addressed кэш**, а не через `temperature=0`. Ключ =
  `sha256(model_id + prompt + json_schema + schema_version)`. Кэш не
  инвалидируется по времени, только по содержимому; «заморозка» — это снимок
  каталога кэша рядом с отправляемым JSON, а не запрет на правки.
- **Греп-гейт:** ни одного имени заёмщика, номера пункта (`6.1`), порогового
  числа, префикса `TXN-`/`ACC-` в `solution/` — только в `tests/` и `eval/`.
  Ничего не зашивать под 3 пункта на заёмщика, 12 сценариев, `USD`/`EUR`,
  русский язык, `ACC-\d{4}`.
- `FACTS` и `SPECS` живут в `eval/expected_extraction.py` как эталон для
  измерения LLM-слоя; боевой прогон их не читает — их берёт только режим
  `facts_source="expected"` через `legacy_spec_to_cellspec`.
- **Не подгонять под публичный набор.** Правило, придуманное под одну ячейку,
  на приватном наборе стоит дороже этой ячейки. Если корень эталонного значения
  не восстанавливается — записать разбор в `docs/ops/` и оставить как есть; так
  сделано с ячейкой на 1.00, где опровергнуты три версии.

## CI и review

- `.github/workflows/ci.yml` — lint, typecheck, pytest, end-to-end
  `python solution/solve.py`, gitleaks (конфиг `.gitleaks.toml`).
- `.github/workflows/claude-review.yml` — автоматический review PR. **Правила
  ревью — в `.github/REVIEW.md`**, тюнить надо там: правка самого workflow
  отключает ревью на том же PR (защита `claude-code-action`).
